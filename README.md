# FIELDGUIDE — Special Warfare Prep

FIELDGUIDE is a public preparation website with pathway-specific score comparisons and an AI-generated, week-by-week training course. Each week includes a stated effort target and personalized progression based on the selected route, entered score gaps, experience, time, equipment, and timeline.

## AI plan API

The browser sends the selected pathway and service route, fitness scores and their supplied comparison targets, optional age, recent training and recovery, training experience, availability, equipment, pool access, sports/prep background, focus, and an optional restriction note to the hosted AI service. It does not send the user's email, password, name, or event-search location to the plan generator. The server forwards the profile and the generated draft to Anthropic's Claude Messages API for generation and a separate review that attempts to correct problems before returning a plan. If review or final validation fails, the server does not return the unreviewed draft. The review adds API usage and latency; it cannot guarantee that a plan is error-free or medically appropriate. Anthropic generally deletes API inputs and outputs within 30 days, subject to exceptions. See [Anthropic's data retention information](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data). Plan generation requires an account, a same-origin session and a CSRF token, and is limited to five requests per account and IP per hour. These limits are held in the server process and reset on restart; sign-in and rate limits are not a guaranteed spending cap. Provider usage may incur charges. The default model is `claude-sonnet-5-5`; set `ANTHROPIC_MODEL` to another compatible model if needed. Plans are generated and reviewed in blocks of up to four weeks, so a 100-week plan can require up to 50 paid API calls. Builds run in server memory; keep the browser open while the progress screen is active. A server restart or a prolonged disconnection ends the build, and completed job data is retained in memory for up to two hours.

For each supported pathway, the server resolves the selected role to its own conditioning priorities, route context, and official reference before passing them to both the generator and reviewer. These are planning guidance, not verified current standards or an official program; users should confirm requirements with the relevant service. Pool access, restrictions, age, current workload, and recovery still govern the suggested work.

## Accounts and saved plans

Users can create an account with an email address and password, sign in with a secure HTTP-only session cookie, and explicitly save, reopen, or delete their training plans. Account email and password are never included in the AI plan request. Passwords are stored as salted scrypt hashes. Saved plan contents are encrypted with AES-256-GCM before they are written to Postgres. A separate owner-only dashboard at `/admin.html` provides read-only access to account emails and saved plan details, including scores and restriction notes. The dashboard never displays password hashes or session tokens. Its access key must be configured as a private server secret and its session expires after 12 hours. Deleting an account removes its saved plans and sessions.

Saving is optional and is performed only after the user chooses **Save to my account**. A saved program contains its pathway, route, starting scores, generated schedule, and any restriction note included in the original profile. Event-search location is not saved. Data remains until the user deletes it or the database is removed. Sessions expire after 30 days. Email verification and password reset are not configured yet; users should use an email they control and keep their password safe.

The account API requires a Postgres `DATABASE_URL` and a `PLAN_ENCRYPTION_KEY` containing 64 hexadecimal characters. The private dashboard also requires a unique `ADMIN_ACCESS_KEY` with at least 32 bytes. Keep all three as server-side secrets; never publish them in this repository or in browser code. The database schema is created by the server at startup. The encryption key must remain available to decrypt saved programs; changing or losing it makes existing saved program contents unreadable.

### Supabase Free Postgres setup

The server uses the standard PostgreSQL `pg` driver, so a Supabase database works directly without exposing Supabase keys to the browser. Create a Supabase project, open **Connect**, and copy the **Session pooler** connection string (port `5432`). Replace its password placeholder, retain `sslmode=require`, and set the full string as `DATABASE_URL` in the Render service's private environment settings. Reserved characters in the password must be URL-encoded. Do not use a Supabase `anon` or `service_role` API key here. Also set `PLAN_ENCRYPTION_KEY` and `ADMIN_ACCESS_KEY` in Render; save changes and redeploy. Confirm `/health` reports both `accountsAvailable` and `adminConfigured` as `true`, then open `/admin.html` and sign in with the dashboard key.

Supabase Free currently includes a 500 MB database per project and can pause projects after a week of low activity. Plan for the database to need resuming if it is inactive; check Supabase's current plan limits before relying on it for continuous availability.

For Supabase hosts, the server uses the bundled public `certs/supabase-root-2021.crt` certificate and verifies both the certificate chain and hostname. It removes conflicting SSL URL parameters before passing the verified TLS settings to `pg`. The certificate comes from Supabase's dashboard source (`https://supabase-downloads.s3-ap-southeast-1.amazonaws.com/prod/ssl/prod-ca-2021.crt`); SHA-256 fingerprint: `807025ad50d4ed219d2c9c7d299c004f824eb00cf7f65afef607d07b72e6cafa`. Its expiry is April 26, 2031; update it when Supabase rotates its root. Keep the certificate file with the server deployment.

## Run the server

Requires Node.js 20 or newer. Install dependencies with `npm install`, configure `ANTHROPIC_API_KEY`, `DATABASE_URL`, `PLAN_ENCRYPTION_KEY`, and `ADMIN_ACCESS_KEY` in the server environment, then run `npm start`. The server hosts the static pages and exposes `POST /api/plan-jobs` with authenticated status and cancellation endpoints, account endpoints under `/api/auth` and `/api/plans`, owner dashboard endpoints under `/api/admin`, and `GET /health`. It binds to `0.0.0.0` and uses the platform-provided `PORT` when deployed.

Never place service credentials in `index.html` or any other browser-delivered file. Set usage alerts or spending controls in the Anthropic Console.

## Deploy

The project uses GitHub Pages as its public entry point and Render for the canonical website and API. The Pages entry redirects to the Render site so account cookies remain same-origin. Render builds with `npm install --omit=dev` and starts with `npm start`. Configure `ANTHROPIC_API_KEY`, `DATABASE_URL`, `PLAN_ENCRYPTION_KEY`, and `ADMIN_ACCESS_KEY` as Render secrets. Keep `index.html`, `admin.html`, `.nojekyll`, `robots.txt`, and `qualification-guides/` together at the published site root so the guide links work.

FIELDGUIDE is an independent preparation resource, not an official military recruiting or medical source. Verify current requirements with the relevant service and review AI-generated training with a qualified professional. The intensity reference is Jake Zweig’s publicly described hard/easy training cycles, recovery weeks, and tapering; FIELDGUIDE does not reproduce his paid program or claim identical weekly volume.
